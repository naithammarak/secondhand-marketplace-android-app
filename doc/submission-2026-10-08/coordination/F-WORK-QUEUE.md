## รายละเอียดคิว 1 — แบรนด์ที่พิมพ์เอง

- แก้การตรวจฟอร์มและ sync ตัวเลือกให้เก็บชื่อที่พิมพ์เอง ไม่แทนด้วย “ไม่ระบุแบรนด์” และส่ง `brand_name` เมื่อไม่มี ID; แบรนด์เดิมส่ง `brand_id` ต่อไป
- API create/update ตรวจชื่อ 1–255 ตัวอักษร ใช้แบรนด์เดิมถ้าชื่อตรงกัน หรือเพิ่มใน transaction เดียวกับสินค้า ไม่มีการเปลี่ยน schema/migration
- ผลทดสอบและลำดับ rollout อยู่ใน [F-BRAND-FIX-2026-10-04.md](../reports/F-BRAND-FIX-2026-10-04.md)
- ต้อง deploy API ที่รับ `brand_name` ก่อนแจก APK ใหม่ และยืนยัน B1a บนเครื่องจริงหลังได้รับอนุญาต

## รายละเอียดคิว 2 — อัปโหลดรูปลงขาย

- อาการที่ผู้ใช้แจ้ง: ลงรูปไม่ได้ ขึ้นข้อความ “เครือข่ายขัดข้องกรุณาลองใหม่”
- ผู้ใช้แจ้งเพิ่มเติมว่าเพื่อนอัปโหลดไม่ได้เช่นกัน; ผลตรวจและแนวทางแก้อยู่ใน [F-UPLOAD-DIAGNOSIS-2026-10-04.md](../reports/F-UPLOAD-DIAGNOSIS-2026-10-04.md)
- จุดที่พบข้อความในโค้ด: `mobile/src/services/image-upload-service.ts` แปลง exception ที่ไม่อยู่ในกลุ่มที่แยกไว้เป็น `network-error` และข้อความ “เครือข่ายขัดข้อง กรุณาลองใหม่” จึงยังสรุปไม่ได้ว่าอินเทอร์เน็ตของโทรศัพท์เสีย
- เส้นทางที่ต้องตรวจ: `pick-product-image.ts` → `image-upload-service.ts` → `POST /products/images/upload` → `backend/app/api/product_uploads.py` → Storage และข้อมูล pending upload
- ตรวจการอ่าน URI ของไฟล์บน Android และ multipart request ก่อนเทียบ HTTP status/request_id กับ API/Auth/Storage; ตรวจ timeout และการลองซ้ำด้วย หลักฐานต้องปกปิด token, credentials และข้อมูลส่วนบุคคล
- เพิ่มการตรวจหลังแก้: อัปโหลดสำเร็จ, ข้อความเมื่อ request ล้มเหลว, การลองใหม่, และข้อมูลฟอร์ม/รูปเดิมไม่หาย ยืนยันบน APK จริงก่อนบันทึก PASS

## รายละเอียดคิว 3 — ยืนยันตัวตนขอเปิดร้าน

- อาการที่ผู้ใช้แจ้ง: เหมือนว่าจะส่งคำขอยืนยันตัวตนในหน้าขอเปิดร้านไม่ได้ ยังไม่ได้ระบุข้อความที่หน้าจอ
- โค้ดเดิมของ `mobile/src/services/verification-service.ts` แนบ `id_card_image` ด้วย `{ uri, name, type }` เมื่อเป็น native เช่นเดียวกับโค้ดอัปโหลดสินค้าเดิม
- [F-UPLOAD-REPRO.mjs](../reports/F-UPLOAD-REPRO.mjs) รักษาบริการทั้งสองที่ commit ก่อนแพตช์ และทำซ้ำ `network-error` ก่อน HTTP ด้วย Expo serializer จริง โดยไม่ส่งข้อมูลร้าน/ธนาคาร/รูปบัตรจริงออกนอกเครื่อง
- ผลแก้และคำสั่งตรวจอยู่ใน [F-VERIFICATION-FIX-2026-10-04.md](../reports/F-VERIFICATION-FIX-2026-10-04.md): ใช้ Expo File, แสดงข้อผิดพลาดตรงช่องรูปบัตรเมื่อไฟล์หาย และไม่ส่งคำขอที่ถูกยกเลิกหลังเปลี่ยนบัญชีระหว่างรอ token
- งานยืนยันที่เหลือ: สร้าง APK ใหม่ ตรวจ Auth/private Storage และการบันทึก/อ่านสถานะ PENDING บนเครื่องจริงตามสิทธิ์ที่ได้รับ
