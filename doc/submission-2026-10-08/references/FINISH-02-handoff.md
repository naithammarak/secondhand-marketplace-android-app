# FINISH-02 / BE — outbound and return through existing Courier (copy-ready v1)

**Objective:** Create exactly one server-derived TO_BUYER or TO_SELLER leg after inspection, and extend the existing Courier routes to prove delivery for those legs. [Decision register](FINISH-contract-decisions.md) and [fixtures](FINISH-api-fixtures.md) are the API contract proposals.

**Base/dependencies:** Start from L1's integrated candidate SHA containing FINISH-01, #112 CERT decision, #113 INSPECT/Wondee and DB1's Seller snapshot/COURIER schema, all reviewed at G0/G1/G2. Recheck head/status and `AGENTS.md`; use an isolated worktree. Owner BE coordinates with DB1 (migration) and COURIER-02 (existing route owner). Never build a second Courier router or shipment/proof table.

**Files/interface:** Extend `backend/app/api/inspections.py` or factor its existing Courier helpers into one shared service while retaining `/admin/shipments/{id}/assign-courier`, `/courier/shipments`, `/courier/shipments/{id}/proofs`, `/courier/shipments/{id}/confirm-delivery`, `/shipment-delivery-proofs/{id}`, and `POST /inspections/{id}/receive`. Add `POST /orders/{id}/fulfillment` for assigned active Inspector: `{ "carrier":"Demo Courier", "tracking_number":"DEMO-42" }` → `201 {order_id,order_status,shipment}`. Under Order lock, final PASS/MINOR_ISSUE + persisted CONFIRM selects TO_BUYER and Order `ship_*`; negative result or REJECT selects TO_SELLER and immutable Seller `return_*`. No client leg/address/party. Reuse one `Shipment` with unique `(order_id,leg)` plus DB1's at-most-one outbound leg rule. If Seller return snapshot absent, return `409 fulfillment_destination_missing`, leave HELD and no shipment. Existing legacy Orders require explicit owner-led remediation, never Buyer/profile fallback.

COURIER-02 extends assignment/queue/upload/confirm/read to all three legs, with active assigned Courier rechecked on every write, minimal current destination, private authenticated bytes and 1–3 selected readable proof IDs. Confirmation request `{ "proof_ids":[21] }` binds confirmed selected proofs under lock; TO_BUYER delivery sets `DELIVERED_PENDING_BUYER` and fixed `receipt_deadline_at = courier_delivered_at + 72h`; TO_SELLER delivery sets `RETURNED_TO_SELLER` + HELD. Return delivery commits independently of settlement and then invokes the FINISH-04 shared service or leaves a durable retry candidate; never report REFUND on delivery commit alone. Keep Inspector center receipt separate and unchanged in meaning. Use the existing Order/Inspection idempotency convention with successful command record in the same DB transaction.

**Acceptance:** Four final results × decision gate choose the correct sole leg; no positive outbound without CONFIRM, no decision for negative result, no cross-Order destination. Wrong/inactive/unassigned Courier, 0/4/foreign/deleted/unreadable proofs, duplicate/mismatched key and concurrent confirmations cannot create delivery/deadline twice. Seller cannot read Buyer destination/TO_BUYER proof; Buyer/Inspector/Courier reads are scoped. Return proof commit survives injected settlement failure and TIMER can find it. Verify actual private Storage separately from mocked/local tests.

**Stop/escalate:** Stop implementation if no immutable Seller snapshot or no integrated decision FK; do not invent a new address provider. If COURIER-02 is being edited concurrently, agree on one file owner and a stacked merge order before touching `inspections.py`.
