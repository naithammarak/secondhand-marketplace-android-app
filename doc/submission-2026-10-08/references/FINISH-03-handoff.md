**Files/interface:** Add `backend/app/services/order_settlement.py` (or candidate equivalent) exposing one `settle(order_id, kind, source, reason, operation, actor)` transaction path for RELEASE/REFUND with server-derived amount/recipients. Add `GET /orders/{id}/delivery` and redacted history/final Order projections. `POST /orders/{id}/confirm-receipt` `{}` by active owning Buyer before deadline atomically records receipt source BUYER and RELEASE → `COMPLETED`/`SOLD`; `POST /orders/{id}/report-not-received` `{"reason":"Parcel has not arrived"}` stores one immutable report and `DELIVERY_DISPUTED`/HELD. No arbitrary amount or direct status editor. Maintain `Idempotency-Key` replay with fresh authorization and no duplicate history/audit.

**Acceptance:** Buyer receipt + RELEASE + history/command/Order/Escrow/Product is one rollback boundary; injected failure leaves HELD and no receipt. Report before deadline permanently blocks AUTO; report alone never refunds. Concurrent receipt/report/worker/Admin and duplicate keys yield one authorized outcome. Storage missing/unreadable leaves HELD. A current Seller-as-Buyer can act while another Seller cannot; Admin/Courier/Inspector cannot buy by role. Historical Receipt remains readable and Payment stays successful; final status reflects settlement. Test on independent PostgreSQL connections, not only SQLite/mocks.
