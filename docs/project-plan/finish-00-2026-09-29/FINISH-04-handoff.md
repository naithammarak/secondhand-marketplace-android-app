# FINISH-04 / BE — REFUND in the FINISH-03 service (copy-ready v1)

**Objective:** Add full simulated REFUND for proven return, seller no-ship, and audited Admin non-receipt resolution. Reuse FINISH-03's single settlement service, ledger, lock order, command/history and simulation guard. [Decision register](FINISH-contract-decisions.md), [fixtures](FINISH-api-fixtures.md).

**Base/dependencies:** Same integrated candidate and BE owner as FINISH-03, with FINISH-01 schema and FINISH-02 return proof. Seller no-ship can be implemented against paid Order/Escrow before return path is ready, but must use the identical service and coordinated TIMER-01 runner. Recheck PR heads, `AGENTS.md`, migration history and current code before editing.

**Files/interface:** Extend `backend/app/services/order_settlement.py` with REFUND kind, server-derived Buyer recipient and `order.total_amount` from locked snapshot, zero seller payout/retained allocations, `REFUNDED` Escrow/Order and Product `CANCELLED`; leave original Payment/Receipt intact. Reason/source pairs: `RETURN_DELIVERY` + `BUYER_REJECTED_INSPECTION|INSPECTION_NOT_AS_DESCRIBED|INSPECTION_FAKE`; `SELLER_NO_SHIP` + `SELLER_NO_SHIP`; `ADMIN_RESOLUTION` + `DELIVERY_REVIEW_REFUND`. Return refund requires confirmed readable TO_SELLER proof and `RETURNED_TO_SELLER`; Admin refund requires durable non-receipt report, scoped audit/reason/evidence references and no client amount. No-ship requires `paid_at + 72h`, `WAITING_SELLER_SHIP`, no committed timely TO_CENTER shipment, HELD and no existing settlement. Coordinate with INSPECT/ORDER owner to make `ship-to-center` reject at/after same deadline under Order lock even when worker is down. Failed return-refund remains a durable `RETURNED_TO_SELLER` + HELD retry candidate; TIMER-01 invokes this service, never its own ledger.

**Acceptance:** Each reason returns exactly original full held amount; no double/opposite settlement, no payout/relist, no deleted Payment/Receipt. Wrong return leg/proof, negative result with TO_BUYER, missing snapshot, late/no-ship race and unauthorized Admin fail without money change. Inject DB/Storage/service crash after return proof commit: worker retries once to REFUNDED. Two workers and Buyer/Admin races prove one terminal record with independent DB connections. Keep `settlement_status=HELD` and truthful API response until commit.

**Stop/escalate:** Stop if a separate REFUND service/ledger is proposed or if seller ship and no-ship timer cannot share the Order lock and deadline rule. TIMER-01 deployment, actual private Storage and Android flows remain separate acceptance gates.
