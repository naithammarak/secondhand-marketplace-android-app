# Admin review of seller verifications (ตรวจคำขอยืนยันตัวตน)

ทางเข้า: หลัง Login ด้วยบัญชีที่ backend ตอบว่า role `ADMIN` จะมีปุ่ม **ตรวจคำขอยืนยันตัวตน**
บนหน้าหลัก กดแล้วเข้าหน้า `/admin-verifications` บัญชีบทบาทอื่น (รวมถึง `INSPECTOR`)
ไม่เห็นปุ่มนี้ และถ้าเปิด path ตรง ๆ จะเห็นเพียงข้อความว่าหน้านี้สำหรับผู้ดูแลเท่านั้น
เพราะทั้งสี่ endpoint ตอบ `403` ให้บทบาทอื่นก่อนแตะข้อมูลคำขอ

## สิ่งที่ต้องเตรียมก่อนทดสอบ

1. **Backend**
   - รัน migration ล่าสุด: `alembic upgrade head`
     (เพิ่ม `verifications.created_at` และ `verifications.reviewed_by`)
   - `SUPABASE_SERVICE_ROLE_KEY` และ bucket private ตามเอกสาร
     [seller-verification.md](./seller-verification.md) — ใช้ key เดิมออกลิงก์ชั่วคราวของรูปบัตร
     ถ้ายังไม่ตั้งค่า storage ปุ่มเปิดรูปบัตรจะแจ้งว่าบริการยังไม่พร้อมใช้งาน
2. **บัญชีทดสอบ**
   - บัญชี `ADMIN` อย่างน้อยสองคน (ใช้ `scripts/assign_test_role.py` ตาม `doc/plan.md`)
     เพื่อทดสอบกรณีคำขอถูกอีกคนตรวจไปแล้ว
   - บัญชี `SELLER` ที่ส่งคำขอค้างไว้อย่างน้อยหนึ่งใบ

## API ที่ใช้

| Method | Path | ผลลัพธ์ |
| --- | --- | --- |
| GET | `/admin/verifications?status=&limit=&offset=` | รายการคำขอตามสถานะ (`PENDING` เป็นค่าเริ่มต้น) พร้อม `total` |
| GET | `/admin/verifications/{id}` | รายละเอียดคำขอหนึ่งใบ |
| GET | `/admin/verifications/{id}/id-card` | ลิงก์ชั่วคราวของรูปบัตร (อายุ 120 วินาที) |
| POST | `/admin/verifications/{id}/decision` | บันทึกผล `{"decision": "APPROVED" \| "REJECTED", "reject_reason": "..."}` |

รหัสตอบกลับที่แอปจัดการ: `401` ต่ออายุ session แล้วลองใหม่หนึ่งครั้ง, `403` ไม่ใช่ผู้ดูแล,
`404` ไม่พบคำขอหรือไม่มีรูปบัตร, `409` คำขอถูกตรวจไปแล้ว (`detail.reviewed_by_name`),
`422` เหตุผลไม่ผ่าน (`detail.fields.reject_reason`), `502` เปิดรูปบัตรไม่ได้

API ไม่ส่งเลขบัญชีเต็มและไม่ส่ง path ของรูปใน storage กลับมาที่เครื่องผู้ดูแล
รูปบัตรเปิดดูได้ผ่านลิงก์ชั่วคราวเท่านั้น และแอปจะขอลิงก์ก็ต่อเมื่อกดปุ่ม "เปิดดูรูปบัตรประชาชน"

## สิ่งที่ต้องตรวจด้วยมือ

- **รายการรอตรวจ:** เห็นชื่อผู้ขาย อีเมล ธนาคาร ชื่อบัญชี เลขบัญชี 4 ตัวท้าย และเวลาที่ส่งคำขอ
  เรียงจากใบที่ส่งมาก่อน
- **หลักฐาน:** กด "เปิดดูรูปบัตรประชาชน" → เห็นรูปจากลิงก์ชั่วคราว รอเกิน 2 นาทีแล้วกดโหลดใหม่
  ต้องได้ลิงก์ใหม่ ถ้า API ไม่อนุญาตต้องเห็นข้อความแทนรูป ไม่ใช่หน้าจอว่าง
- **อนุมัติ:** กด "อนุมัติ" → รายการถูกรีเฟรชจาก backend คำขอหายจากคิว และผู้ขายเห็นสถานะ
  "อนุมัติแล้ว" ในหน้ายืนยันตัวตนผู้ขาย
- **ปฏิเสธ:** กรอกเหตุผลแล้วกด "ปฏิเสธ" → ผู้ขายเห็นเหตุผลเดียวกันและส่งคำขอใหม่ได้
- **ปฏิเสธโดยไม่มีเหตุผล:** เว้นเหตุผลว่างหรือกรอกสั้นกว่า 5 ตัวอักษรแล้วกด "ปฏิเสธ" →
  ข้อความสีแดงใต้ช่องเหตุผล และ **ไม่มีการยิง API**
- **กันกดบันทึกซ้ำ:** กดปุ่มรัวระหว่างบันทึก ปุ่มทั้งคู่ถูกปิดและยิง API ครั้งเดียว
- **อีกคนตรวจไปแล้ว:** เปิดคำขอใบเดียวกันด้วยผู้ดูแลสองบัญชี ให้คนแรกกดอนุมัติ แล้วคนที่สองกดปฏิเสธ →
  ต้องเห็นข้อความว่าคำขอถูกตรวจไปแล้วโดยใคร ผลของคนแรกไม่ถูกทับ และรายการถูกรีเฟรชอัตโนมัติ
- **รายการว่าง:** ไม่มีคำขอรอตรวจ → เห็นข้อความ "ไม่มีคำขอรอตรวจในขณะนี้" ไม่ใช่หน้าจอว่าง
- **โหลดล้มเหลว:** ปิดเน็ตแล้วเข้าหน้านี้ → เห็นข้อความผิดพลาดพร้อมปุ่ม "ลองใหม่อีกครั้ง"
  เปิดเน็ตแล้วกดลองใหม่ต้องโหลดสำเร็จ
- **บัญชีที่ไม่มีสิทธิ์:** ล็อกอินด้วย `BUYER`, `SELLER` หรือ `INSPECTOR` แล้วเปิด `/admin-verifications` →
  ไม่เห็นข้อมูลคำขอใด ๆ
- **เปลี่ยนบัญชี / Logout:** ออกจากระบบแล้วเข้าด้วยบัญชีอื่น ต้องไม่เห็นรายการของบัญชีก่อนหน้า
  แม้ชั่วขณะระหว่างโหลด
